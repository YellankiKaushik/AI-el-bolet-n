Primary documentation checked: [pricing](https://buttondown.com/pricing), [API availability](https://marketing.buttondown.email/features/api), [standard embedded signup](https://docs.buttondown.com/building-your-subscriber-base), [double opt-in](https://docs.buttondown.com/double-opt-in), [default sender](https://docs.buttondown.com/welcome-to-buttondown), [API draft creation](https://docs.buttondown.com/api-emails-create), [single-mailbox draft send](https://docs.buttondown.com/api-emails-send-draft).

At review time Buttondown advertised the first 100 subscribers free and API access on all plans; pricing assumes at most one list email per day. A custom domain is optional: its shared sender can use `username@buttondown.email`. Domain-free signup/account confirmation is still required. The standard embedded subscribe endpoint is different from additional campaign “Forms”, which are documented as Standard-plan features. Do not buy an add-on or assume a connected account has any entitlement without checking it.

Once the actual account exists, set only the public `VITE_BUTTONDOWN_USERNAME` in the portfolio. The HTML form posts directly to Buttondown; the provider manages confirmation and unsubscribe. No second public subscriber database or client API token is introduced. Keep double opt-in enabled and verify confirmation/unsubscribe with the owner before public signup activation. Current browser signup testing intercepts a fictional endpoint; it is MOCKED, not live acceptance.

The private `tools/buttondown_draft.py` module supports explicit draft payload creation, private-token API requests, durable exclusive reservations, provider status reconciliation and an opt-in single-mailbox preview. `create_draft(public_edition, PRIVATE_LEDGER)` posts only status `draft` with the portfolio permalink. Timeouts preserve a reservation and require reconciliation before retry. `reconcile(provider_id)` retrieves actual status. `send_test(provider_id, PRIVATE_RESERVATION)` requires `BUTTONDOWN_TEST_SEND_ENABLED=true`, an authorized `BUTTONDOWN_TEST_EMAIL`, a provider draft and a unique reservation; it targets exactly that one recipient. Keep `BUTTONDOWN_API_KEY` private and outside every `VITE_` variable. Ledger files belong under ignored private storage.

No bulk-send API is exposed by this adapter. After successful account/sender/inbox/consent acceptance, actual subscriber delivery remains an explicit provider-UI publishing decision by the editor. Reconcile sent/queued/uncertain states rather than resending. Provider request success alone is not proof of inbox delivery. Production activation and the first actual send are BLOCKED until those external account/editorial gates pass.
